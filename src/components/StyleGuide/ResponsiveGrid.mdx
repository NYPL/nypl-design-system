## Overview

Pages should be designed and built using a responsive grid system that
dynamically adjusts based on the screen size. Using a responsive grid system
helps to ensure consistent layouts across NYPL website.

The structure of the responsive grid will scale in a fluid system as the
viewport width increases from small to large. The defined NYPL breakpoints will
determine when default adjustments are applied to the grid.

## Terminology

The following terms are used through the documentation, so it is important to
understand what they mean.

### Breakpoints & breakpoint ranges

A breakpoint defines a specific pixel value within the viewport width spectrum,
but when we talk about a breakpoint, we often think about it in terms of the
width range that is covered by the breakpoint (i.e. breakpoint range). With
that in mind, the NYPL Reservoir Design System will designate four actual
breakpoints and from that we will define five breakpoint ranges:

#### Breakpoints

- 480px
- 768px
- 1024px
- 1280px

#### Breakpoint ranges

- Small mobile (base): less than 480px (see the <Link href="#small-mobile-less-than-480px" target="_self">small mobile visual reference</Link>)
- Large mobile (s): 480px - 767px (see the <Link href="#large-mobile-480px---767px" target="_self">large mobile visual reference</Link>)
- Small tablet (m): 768px - 1023px (see the <Link href="#small-tablet-768px---1023px" target="_self">small tablet visual reference</Link>)
- Large tablet (l): 1024px - 1279px (see the <Link href="#large-tablet-1024px---1279px" target="_self">large tablet visual reference</Link>)
- Desktop (xl): 1280px and greater (see the <Link href="#desktop-1280px" target="_self">desktop visual reference</Link>)

### Grid anatomy

The anatomy of a responsive grid is made up of elements that scale in a fluid
system as the device and viewport increases from small to large.

### Perceived columns

- The 12-columns that are the foundation of a responsive grid system are often
  grouped to create "perceived columns."
- Perceived columns define the basic structure of a page or page section.

## Best practices and recommendations

### General

- Use white space created by the grid system &ndash; too much dense information can be
  disorienting and overwhelming
- Avoid breaking alignment or slightly oversizing a container to stick out for
  visual interest or to add emphasis
- Create relationships and hierarchy between content elements by using the margins
  and gutters in the grid shared by the page layout
- Avoid rendering too much content in narrow column widths &ndash; based on the
  NYPL typography recommendations, the width of a text block should be at least
  300px (**NOTE:** some viewport width edge cases will be less than the 300px
  width recommendation and that is okay)

### Cards

- The desired card layout (`"row"` vs. `"column"`) should be considered when
  setting the structure of a card grid
- The number of columns in a card grid should align with the recommended
  "perceived columns" for a breakpoint range
- For card grid layout recommendations, refer to the <Link
  href="https://www.figma.com/design/qShodlfNCJHb8n03IFyApM/Main?node-id=91252-91410&t=WPK9UR9vJDTPfzUr-11"
  target="_blank">Responsive Grid System</Link> page in the Reservoir Visual
  Design Library

### Mobile first

- Begin designing with the smallest viewport width (one column) for small
  devices like a phone.
- Complete and optimize the layout for each successive viewport width.
- Inspect responsive displays in between each breakpoint for how content
  responds across the fluid spectrum.

## General information

Cards are used extensively throughout NYPL web apps for navigational purposes.
They are used in search results and on landing pages. They can represent
distinct items, like books and events, or signify site landing pages and
sections. They may contain a single link or present multiple links and buttons.

## Full-click functionality

Navigational cards designed to link to a singular destination should be
configured with [full-click
functionality](/docs/components-basic-elements-card--docs#card-with-full-click-functionality),
rendering the entire card as a clickable element.

It is recommended for NYPL web apps to utilize the DS Card component, as it
provides a hover state for the full-click functionality, thereby indicating that
the complete card is a clickable element. To review the DS Card styling, please
consult the <Link href="https://nypl.github.io/design-team-prototypes/full-click-card-styles/#background-image-fade" variant="external">Default background color & image fade</Link> POC.

Currently, for cards not utilizing the DS Card component, identical links are
frequently applied to both the heading and image within the card. This results
in a scenario where two distinct elements direct to the same destination.
Implementing full-click functionality will alleviate this redundancy.

## Distinct links

Navigational cards that present links to multiple destinations or a single
button element—excluding links that look like buttons—should not utilize
full-click functionality.

While the DS Card component permits the application of full-click functionality
regardless of card content, NYPL patterns do not recommend this approach.
Instead, the expectation is that each clickable element should be distinct and
full-click functionality should not be used.

## Overview

A brief, informative message that appears when a user hovers or focuses on an
element.

## Accessibility

The DS `Tooltip` component is implemented with Chakra UI and Chakra handles the
appropriate `aria-describedby` attribute for the element that the tooltip is
associated with.

The `Tooltip` component is accessible via keyboard. The color contrast between
foreground color and background color is 4.5:1. If text size is 200%, the
button scales with text so there is no overlap.

If a tooltip is associated with a form control (text, radio, checkbox, etc),
the text for the tooltip should be included in the form control label.

Resources:

- [W3C WAI ARIA Tooltip](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/)
- [MDN ARIA: tooltip role](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Roles/tooltip_role)
- [Chakra UI Tooltip](https://chakra-ui.com/docs/components/overlay/tooltip)

## Best practices

Tooltips are often misunderstood and therefore not used correctly. To implement
a tooltip correctly, start by following the recommendations below.

- **Only interactive elements should trigger tooltips.** (ex. form fields, links,
  etc.)
- Tooltips should directly describe the UI control that triggers them. (i.e. do
  not create a control purely to trigger a tooltip that describes something
  else)
- Do not put essential information in tooltips. (i.e. always assume tooltip text
  may never be read)
- Write concise tooltip text.
- Avoid rich text formatting and images.
- Do not add interactive content. (no links or buttons)

Resources:

- [Tooltips in the time of WCAG 2.1](https://sarahmhigley.com/writing/tooltips-in-wcag-21)

## Examples

### Tooltips on form options

- For correctly positioning, use the `shouldWrapChildren` prop when adding a
  tooltip to the `Checkbox`, `Radio`, and `Toggle` components.
- The underlying `ref` of the `Checkbox`, `Radio`, and `Toggle` components point
  to a visually hidden input element.
- Using `shouldWrapChildren` ensures that the size of the visually hidden
  element is in sync with the rendered visual control.

<Canvas of={TooltipStories.OnFormElements} />

### Tooltip on Image component

- Do not use the `shouldWrapChildren` prop when adding a tooltip to an `Image`
  component using the `aspectRatio` prop.
- This combination of props will cause the `Image` component's `size` prop to
  not function properly.

### Disabled buttons

- By default, the `Tooltip` is not shown for a disabled `Button`.
- To show the `Tooltip` on a disabled `Button`, set the `shouldWrapChildren`
  prop to `true`.

<Canvas of={TooltipStories.DisablingTooltipButton} />

### Placement

- The `placement` prop can be used to adjust the tooltip's location relative to
  its children: `"top"`, `"bottom"`, `"left"`, or `"right"`.
- It is recommended to use the default `"top"` placement.

<Canvas of={TooltipStories.Placement} />

### Offset

- The `offset` prop sets the XY coordinate position of the tooltip in relation
  to its reference element.
- The values of the `offset` prop are static pixel values, so make sure to check
  where the tooltip displays on all breakpoints.
- It is **not** recommended to set custom `offset` values unless there are
  extenuating circumstances.

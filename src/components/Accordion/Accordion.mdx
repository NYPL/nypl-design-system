## Overview

<Description of={AccordionStories} />

The `Accordion` component displays a list of high-level options that can expand
and collapse to reveal associated sections of content. This component pushes
existing content on the page down. Each accordion item is self contained, but
when the data for multiple accordions is passed in through the `accordionData`
prop, the `Accordion` components are grouped together and rendered under a
single element. When grouped like this, each `Accordion` component still opens
and closes independent from the others in the group.

The only way to render an `Accordion` component is to pass in an array of
objects with `label` and `panel` properties, and optional `variant`,
`isDisabled`, `ariaLabel`, and `buttonInteractionRef` properties for each
accordion item. Note that you can pass in a string or DOM elements into the
`panel` property in each object. This approach is needed because, internally,
we deal with the logic to render the necessary icon, Chakra components, and
styles.

The `variant` prop can be used to change the accordion button's background
color. It takes a value of `"default"` for `"ui.white"`, `"warning"` for
`"ui.status.primary"`, and `"error"` for `"ui.status.secondary"`. The optional
`panelMaxHeight` prop determines the maximum height of the `Accordion`'s panel
when expanded. If the content within the panel exceeds the `panelMaxHeight`, a
scrollbar will appear.

The `isDisabled` prop sets the `disabled` property for that accordion button
and applies more muted colors.

The `buttonInteractionRef` prop can be used to set a programmatic reference to
the main button element in each accordion with an accordion group.

<Source
  code={`
  // Internally defined type and exported for use in any application.
  export interface AccordionDataProps {
    ariaLabel?: string;
    buttonInteractionRef?: any;
    label: string | JSX.Element;
    panel: string | React.ReactNode;
    variant?: AccordionVariants;
  }
  // ...
  const accordionData: AccordionDataProps[] = [
    {
      ariaLabel: "Tom Nook, known in Japan as Tanukichi",
      label: "Tom Nook",
      panel: (
        <Card
          imageProps={{
            alt: "Alt text",
            aspectRatio: "twoByOne",
            src: "https://play.nintendo.com/images/AC_Tom_FRYtwIN.17345b1513ac044897cfc243542899dce541e8dc.9afde10b.png",
          }}
          isCentered
          layout="row"
        >
          <CardHeading level="h4" id="heading1">
            Tom Nook
          </CardHeading>
          <CardContent>
            Tom Nook, <b>known in Japan as Tanukichi</b>, is a fictional
            character in the Animal Crossing series who operates the
            village store.
          </CardContent>
        </Card>
      ),
      variant: "default",
      isDisabled: false,
    },
  ];
  // ...
  <Accordion accordionData={accordionData} />
`}
  language="tsx"
/>

An `aria-label` may also be passed in on the component level:

<Source
  code={`
  <Accordion accordionData={accordionData} aria-label="Tom Nook"/>
`}
  language="tsx"
/>

Doing the above will apply the `aria-label` to all accordion buttons
in the group. Please note, however, that if an `ariaLabel` is also
present as a key in the `accordionData` entries, the key will override
the `aria-label` passed to the `Accordion`.

## Accessibility

<Banner
  content={
    <>
      <strong>NOTE:</strong> It's recommended to pass an <code>id</code> value
      for accessibility requirements. If no <code>id</code> is passed, a random{" "}
      <code>id</code> will be generated.
    </>
  }
  mt="s"
  mb="s"
  variant="recommendation"
/>

- The `Accordion` follows [U.S. Web Design System (USWDS)](https://designsystem.digital.gov/components/accordion/)
  guidelines:
  - Use the `button` HTML element for screenreaders and keyboards.
  - Use the `aria-expanded` attribute to indicate whether the `Accordion` is
    expanded (`true`) or collapsed (`false`).
  - Use the `aria-controls` attribute to associate the control with the panel.
- This component deviates from USWDS in that the user can open multiple panels.
  Opening one does not collapse already expanded panel.
- The open and close icons are decorative (`aria-hidden` is `true`).
- Visible focus goes around the entire button.
- An `aria-label` attribute can be applied to the accordion button using
  one of the following methods:
  - You may add an `aria-label` directly to the `Accordion` which will apply
    the same value to all accordions within an accordion group.
  - Or you may set a unique value for each accordion by adding
    an `ariaLabel` key to each entry in the `accordionData` array
  - If you add both an `aria-label` to the `Accordion` directly and an
    `ariaLabel` to a particular entry, the latter will take precedence.
- If the user presses the 'esc' key and focus is on an open accordion panel,
  that panel will close and focus will return to the accordion's button.

Resources:

- [W3C WAI-Aria Practices - Accordion](https://www.w3.org/TR/wai-aria-practices-1.1/#accordion)
- [USWDS Accordion](https://designsystem.digital.gov/components/accordion/)
- [Chakra Accordion](https://chakra-ui.com/docs/components/disclosure/accordion)

## Always render the accordion content

By default, the content in an `Accordion` is only rendered when it is opened.
When it is closed, the content gets removed from the DOM. This is an intentional
optimization. However, there will be occasions when you want to always render
the content inside an `Accordion` whether it's opened or closed. Use the
`isAlwaysRendered` prop to always render the `Accordion`'s content.

In the following examples, the first `Accordion` has the default behavior where
the content is removed when it is closed. The second `Accordion` always renders
its content. This is important in this scenario because we want to keep the state
of the content when it is closed. Click on subjects inside both `Accordion`s and
toggle them closed and opened to see the difference.

## Back to Foundations

Reservoir v4 includes everything from simple style updates to breaking changes.
It represents a return to the fundamentals, specifically focusing on the foundational
layers of HTML, CSS, and JavaScript to make our components more accessible, intuitive,
and maintainable. This move will strengthen our understanding and application of
fundamental web technologies.

By aligning with web standards, we aim to:

- Simplify the mental model for developers: fewer abstractions, predictable naming
  conventions and behaviors.
- Continue promoting and supporting accessibility by default: follow semantic HTML
  standards.
- Reduce tech debt and over-engineering: use and allow standard HTML and CSS
  principles and remove tight coupling with JavaScript logic.

## Getting Started

### Step 1

`npm install @nypl/design-system-react-components@4.0.0`

### Step 2

Run `npx tsc --noEmit` or `npm run lint` to output a list of Typescript errors.
This represents the majority of breaking changes you'll need to address.

### Step 3

Start updating your code!

## Breaking Changes

### We anticipate these to be the most common breaking changes.

**Upgrade your Template**\
If your application uses the Reservoir `Template`, you’ll need to refactor your code to
use the new composable Template components.

**Rename “type” props to “variant”**\
We changed prop names from “type” to “variant” to more accurately describe what they do.

If you're using these components, update the following prop names.

| Component        | Old prop         | New prop         |
| ---------------- | :--------------- | :--------------- |
| **Accordion**    | accordionType    | variant          |
| **Banner**       | type             | variant          |
| **Breadcrumbs**  | breadcrumbsType  | variant          |
| **Button**       | buttonType       | variant          |
| **Hero**         | heroType         | variant          |
| **Icon**         | iconType         | variant          |
| **Link**         | type             | variant          |
| **List**         | type             | variant          |
| **Modal**        | type             | variant          |
| **Notification** | notificationType | variant          |
| **Select**       | selectType       | variant          |
| **StatusBadge**  | type             | variant          |
| **TagSet**       | type             | variant          |
| **TextInput**    | textInputType    | textInputVariant |

**Change spacing as needed**\
We removed default spacing from several components and the `noSpace` prop in
`Heading` and `Text`.

- If you’re using the `noSpace` prop, you'll need to remove it.
- If you were relying on default spacing from Reservoir, you may need to add it back
  manually.

| Component                | Spacing removed |
| ------------------------ | :-------------- |
| **Heading**              | `mb='s'`        |
| **HelperErrorText**      | `mt='xxs'`      |
| **HorizontalRule**       | `my='s'`        |
| **Label**                | `mb='xs'`       |
| **List (`ol` and `ul`)** | `mb='s'`        |
| **StyledList**           | `mb='s'`        |
| **Text**                 | `mb='s'`        |

### These are some other updates you may need to make.

**Remove deprecated props and values**\
We removed deprecated props and variants, so if you're still using them, you'll need to update your code. Here’s a list of what's been removed:

Heading
size: “primary”, “secondary”, …
level: “one”, “two”, …
Hero
“secondary” and “fiftyFifty” types
Button
“link” variant (formerly buttonType)
Link
“button” type
Notification
noMargin prop (remove the prop, but make the noMargin styles the default styling)
ProgressIndicator
darkMode prop
StatusBadge
level prop
StyledList
“tag” and “mini” textSize
Text
“mini” and “tag” size
Font Weight Semantic Tokens
“heading.primary”
“heading.secondary”
“heading.tertiary”
“heading.callout”

Adjust aria props to HTML equivalents
Native HTML attributes have replaced explicit aria props.

Accordion: ariaLabel --> aria-label
Banner: ariaLabel --> aria-label
HelperErrorText: : ariaAtomic --> aria-atomic, ariaLive --> aria-live
Notification: ariaLabel --> aria-label

Update id references
We’ve adjusted ids within our components for clarity and consistency, so if you are using Reservoir component ids in tests, styles, or elsewhere in your code, you may need to update them.

Check responsive designs are compatible with new breakpoints
Our breakpoints have changed. We don’t expect this to be a big change, but it’s possible a page may not look as expected on smaller screen sizes and will need to be adjusted.

Rename tableTextSize prop in Table to fontSize

## Non-Breaking Changes

## v3 Support

The Reservoir team will support v3 until the end of Q2 FY26.

### Main Additions and Upgrades

- The `Menu` (new) and `MultiSelect` (v2) components are included in this release.
- Chakra 1.8 does not support React 18, so Chakra has been updated to version
  2.8. **IMPORTANT: If you manually and separately install Chakra in your app,
  make sure to also upgrade it in the `package.json` file.**

General updates can be found in the [Changelog](https://github.com/NYPL/nypl-design-system/blob/development/CHANGELOG.md),
but the main points to note are:

- `StatusBadge` has a new `type` prop.
- There are better responsive styles for the `Heading` and `Text` components.
- The following Chakra 2.8 helpers are now exported through the DS:
  `cookieStorageManagerSSR`, `FocusLock`, `useStyleConfig`, and `useMultiStyleConfig`.

### Major Visual Changes

- `StatusBadge` has updated UI variants.
- `Tabs` adds horizontal scrolling for desktop viewports and improves
  horizontal scrolling for mobile viewports.

## Breaking Changes

### Design System

- The `NewsletterSignup` and `SocialMediaLinks` components have been removed.
  They will be added back in a later version.
- `SimpleGrid` gap values have been updated to include `"grid"` in the prop
  value name. For example, `gap=”grid.xs”`.
- The `Link` component now supports app framework's routing link components. For
  example, `Link` component from Next.js can be used through the `as` prop. The
  previous pattern where the framework's `Link` component was used as a parent
  component is no longer supported.

<Source
  code={`
// Assuming that Next.js 13+ is being used

// Do This
import Link as NextLink from "next/link";
import { Link } from "@nypl/design-system-react-components";

<Link href="/about" as={NextLink}>
  About
</Link>

// Don't Do This
import Link from "next/link";
import { Link as DSLink } from "@nypl/design-system-react-components";

<Link href="/about" passHref>
  <DSLink>About</DSLink>
</Link>
`} language="jsx" />

- The `TagSet` `"filter"` variant has been updated to improve filtering logic in
  consuming apps.
  - Only for the `"filter"` variant, the `tagSetData` prop now
    expects an array of objects with the following required properties:
    `{ label: string, id: string }`. Any additional property can now also be
    added to the object.
  - The `onClick` function now returns the entire data object of the clicked
    tag instead of the tag's "label".

### Chakra UI

- It is recommended to use `cookieStorageManagerSSR` instead of
  `cookieStorageManager` for color mode server-side rendering (SSR). The returned
  value should still used in the `DSProvider`'s `colorModeManager` prop.
- The `FocusLock` component was previously imported from the separate Chakra
  `@chakra-ui/focus-lock` package. In Chakra v2+, `FocusLock` can now be
  imported from the main npm Chakra package. This is now included as an export
  from the DS.

<Source
  code={`
    import { FocusLock } from "@nypl/design-system-react-components";
  `}
  language="jsx"
/>

## Additional Testing Needs

- Due to some JS features and how we test, consuming apps need to add the
  following to their Jest setup file (typically `jest.config.js`). They are
  needed for the following components and hooks: `Tabs`, `Slider`, and
  `useNYPLBreakpoints`. _We are actively working on updates so that consuming
  apps do not have to include these test helpers in future releases._

<Source
  code={`
// Related to the useNYPLBreakpoints hook which is used in: ButtonGroup,
// FeedbackBox, Modal, MultiSelectGroup, and NewsletterSignup.

new MatchMedia();
`}

/>

## Back to Foundations

Reservoir v4 includes everything from simple style updates to breaking changes.
It represents a return to the fundamentals, specifically focusing on the foundational
layers of HTML, CSS, and JavaScript to make our components more accessible, intuitive,
and maintainable.

By aligning with web standards, we aim to:

- Simplify the mental model for developers: fewer abstractions, predictable naming
  conventions and behaviors.
- Continue promoting and supporting accessibility by default: follow semantic HTML
  standards.
- Reduce tech debt and over-engineering: use and allow standard HTML and CSS
  principles and remove tight coupling with JavaScript logic.

## Breaking Changes

### We anticipate the following to be the most common breaking changes.

#### 1. Upgrade your `Template`.

If your application uses the Reservoir `Template`, you’ll need to refactor your code to
use the new composable [Template components](../?path=/docs/components-page-layout-template--docs#overview).

<Banner

  mb="s"
  variant="recommendation"
/>

#### 2. Rename “type” props to “variant”.

We changed the following prop names to more accurately describe what they do.

| List         | type             | variant          |

| Select       | selectType       | variant          |

#### 3. Add spacing where defaults have been removed.

We removed a lot of default spacing, as well as the `noSpace` props in `Heading` and `Text`.

- If you’re using a `noSpace` prop, you'll need to remove it.
- If you were relying on default spacing from Reservoir, you may need to add it back
  manually.

### These are some other updates you may need to make.

#### Remove deprecated props and variants.

We removed deprecated props and variants, so if you're still using them, you'll need
to update your code. You can see a list of what's been removed in [this PR](https://github.com/NYPL/nypl-design-system/pull/1783).

#### Adjust aria props to HTML equivalents.

Native HTML attributes have replaced explicit aria props. For example, `Accordion`'s
`ariaLabel` has been replaced with `aria-label`. You can see a list of aria props that
have been removed in [this PR](https://github.com/NYPL/nypl-design-system/pull/1797).

#### Update `id` references as needed.

We’ve adjusted `id`s within our components for clarity and consistency, so if you're
using Reservoir component `id`s in tests, styles, or elsewhere, you may need to update them.

#### Ensure responsive designs are compatible with the new breakpoints.

Our [breakpoints](../?path=/docs/style-guide-breakpoints--docs) have changed! We don’t
expect this to be too disruptive, but it’s possible a page will not look as expected on
smaller screen sizes and will need to be adjusted.

## Non-Breaking Changes

These updates enhance flexibility, stability, and developer experience without requiring breaking changes to your existing code.

#### A `useResponsiveSpacing` hook was introduced.

[`useResponsiveSpacing`](../?path=/docs/hooks-useresponsivespacing--docs) exports spacing values to generate consistent layouts.
We recommend its usage for custom layout and components.

#### The `id` prop is now optional for all components.

For components that require `id`s to meet accessibility requirements, one will automatically be generated using React's `useId`
hook if none is passed.

#### All components now include a default `data-testid` attribute on their top-level element.

The `data-testid` value follows the pattern `ds-[componentName]` (e.g., `ds-accordion`, `ds-button`).

#### Component prop interfaces have been significantly expanded to accept a wider range of values.

This includes standard native HTML attributes (e.g., `aria-label`, `type` for inputs, `tabIndex`) and all Chakra UI style props
(e.g., `p`, `m`, `bg`, `color`, `sx`).

Refer to the dedicated note above each component's props table for details on how its types were extended.

#### We're no longer throwing errors.

Components like `Breadcrumbs`, `Heading`, and `Image` no longer throw errors (crashing your application) when missing required prop
values.

#### There are no warnings for invalid children.

Components that expect specific child types (e.g., `RadioGroup` expecting `Radio` children) will no longer log warnings reducing
console noise during development.

#### We removed unused code.

The `Header` component was needed for a specific problem that no longer exists and has been removed in v4.

`FilterBar` was deprecated in favor of `FilterBarInline` and `FilterBarPopup`.

The `Autosuggest` documentation was originally included as a guideline for using `react-autosuggest`, but is no longer recommended
due to technical complexity and UX consistency concerns and has been removed in v4.

#### Other optimizations

- We've updated our Storybook version, and given the doc headers a new look and feel.
- We've reduced `React.Children.map` usage in hopes of a performance gain in the components that were using it.
- We've updated some of our internal naming for improved consistency.
- We're utilizing object destructuring for arguments, enhancing readability and maintainability.

The Reservoir team will support v3 until the end of Q2 FY26.

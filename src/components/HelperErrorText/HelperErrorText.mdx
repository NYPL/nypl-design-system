## Overview

`HelperErrorText` renders supporting text. It always renders a container, even
if the text itself is not passed. This pattern guarantees accessibility guidelines
are met if the text content is dynamically updated.

## Component props

`HelperErrorText` composes a Chakra `Box` component, so you may pass
any Chakra `Box` props, as well as the props below.

## Accessibility

In the Reservoir Design System (DS), `HelperErrorText` is always used as a child
component when composing more complex components.

When used with form components, the text is associated with a related input
field by using the `aria-describedby` attribute which ensures that the
`HelperErrorText` is made available to screenreaders.

This component will always render a `<div>` element with an `aria-live="polite"`
attribute even if no text content is passed. This is to ensure that the
accessibility guideline for dynamic content is met.

The example below uses the `HelperErrorText` component to render the red-colored
`"This is error text :("` below the input field. It is referenced with the
`aria-describedby` attribute on the HTML input element. This type of association
is handled automatically by all DS form components.

### ARIA live

By default, `aria-live` is set to `polite` for the `HelperErrorText` component.
`aria-live` determines when text updates should be read by assistive technologies
and the `"polite"` value indicates that updates should be read whenever the user
is next idle (important, but not requiring immediate attention).

If desired, you can pass `aria-live="off"` or `aria-live="assertive"` instead.

The `"off"` value indicates that updates should not be announced. When this
value is passed, the `aria-live` attribute will not be added at all.

The `"assertive"` value indicates that updates should be announced
immediately. This is generally not recommended as it can interruptive
to the user.

In order to meet accessibility guidelines for dynamic content updates, this
attribute is set in the wrapper `<div>` that is always rendered (regardless of
whether the text is present).

<Canvas of={HelperErrorTextStories.AriaControls} />

### ARIA atomic

When `aria-atomic` is set to `true` within an ARIA live region and something in
that region changes, the entire DOM element is presented to assistive technologies.
This is the default behavior of the `HelperErrorText` component. If desired,
you can pass `aria-atomic={false}` instead so that only the change (addition or
removal) is presented.

- [MDN aria-describedby Attribute](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Attributes/aria-describedby)
- [MDN ARIA live regions](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/ARIA_Live_Regions)
- [W3C WAI-ARIA 1.1 - aria-live (property)](https://www.w3.org/TR/wai-aria-1.1/#aria-live)

## HTML and JSX children

The `HelperErrorText` component can render any HTML element or React component
through the `text` prop. Note that the `text` value is always wrapped in a `Box`
with margin top, so if the elements you pass have margin or padding on top, the
text may appear to have too much space.
